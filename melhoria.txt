function dedupeById<T extends { id: string }>(items: T[], next: T | undefined | null) {
  if (!next) return items;
  if (items.some((item) => item.id === next.id)) return items;
  return [...items, next];
}
PARA
function dedupeById<T extends { id: string }>(
    items: T[],
    next: T | undefined | null
) {
    if (!next) return items;

    for (let i = 0; i < items.length; i++) {
        if (items[i].id === next.id) {
            return items;
        }
    }

    const copy = items.slice();
    copy.push(next);

    return copy;
}

Motivo

Evita criar callbacks (some) e reduz pressão no GC.

O maior problema do arquivo

O maior gargalo não é o WebSocket.

É este trecho:

computeMetrics(
    filterCycles(...),
    filterPieces(...)
)

Em uma fábrica produzindo milhares de peças, cada evento recebido faz o frontend percorrer novamente todas as peças e todos os ciclos para recalcular indicadores. Com dezenas de clientes conectados, isso multiplica o trabalho em cada navegador.

O que eu faria (sem alterar a premissa do projeto)

Eu não removeria nenhum dado em tempo real.

Eu manteria exatamente o mesmo comportamento funcional, mas mudaria a estratégia:

índices (Map) para ciclos e peças por data/turno;
cache de métricas invalidado apenas quando chega um novo evento;
atualização incremental dos índices em vez de filtrar arrays inteiros;
redução de cópias desnecessárias de arrays.

Essas mudanças preservam todos os eventos, todas as peças e todos os ciclos exibidos hoje, mas reduzem significativamente o custo de processamento por evento.
